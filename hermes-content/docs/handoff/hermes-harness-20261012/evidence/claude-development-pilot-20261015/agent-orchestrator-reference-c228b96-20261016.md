## Principio reutilizable para Hermes

Separar despacho del ciclo de vida del proceso proveedor: persistir identificador nativo de conversación/turno, transmitir salida como evento, y ante reinicio reconciliar/reconectar al mismo thread antes de considerar un nuevo inicio. El código fuente sirve como referencia de diseño para idempotencia y continuidad; no autoriza copiar una arquitectura basada en CLI local/worker ni reemplazar el objetivo de Cloud nativo y PC-off. La alternativa Codex CLI en GitHub Actions permanece sujeta a la decisión del usuario.

## Actualización: interfaz oficial de Claude Code Cloud

Consulta de documentación oficial Anthropic (16-oct-2026), no ejecutada en esta cuenta:

- La CLI oficial `claude --cloud "tarea"` crea una sesión cloud nueva de claude.ai desde el terminal. El VM remoto clona el remoto GitHub de la rama actual, y la sesión sigue ejecutándose aunque se cierre la laptop; puede observarse desde Claude mobile ([Claude Code on the web, líneas 183–198](https://code.claude.com/docs/en/claude-code-on-the-web#L183-L198)). Por tanto, el uso de CLI puede ser sólo el disparador de un servicio remoto oficial; no equivale automáticamente a ejecución local.
- Para un seguimiento programático de una sesión cloud existente, `claude -p "mensaje" --cloud <session-id>` autenticado con cuenta Anthropic en cualquier máquina encola el mensaje y termina sin esperar respuesta. `--output-format json` devuelve `{ok, session_id, url}` en éxito o `{ok:false,session_id,error}` en error; requiere cuenta Anthropic y política organizacional `allow_remote_sessions` ([Claude Code on the web, líneas 249–271](https://code.claude.com/docs/en/claude-code-on-the-web#L249-L271)). `--cloud` con un texto de tarea y `-p` se rechaza; para nueva sesión la documentación muestra `claude --cloud <task>` ([Claude headless, líneas 49–59](https://code.claude.com/docs/en/headless#L49-L59)).
- Este mecanismo es una interfaz oficial documentada para disparar/encolar trabajo remoto de Claude Code Cloud, distinta del worker del repositorio auditado que arranca CLIs propios. La respuesta JSON sólo acredita que el mensaje fue encolado; no es resultado de ejecución/readback ni prueba de coordinación PC-off del caller. El login, permisos de cuenta, setting organizacional, retorno/artefacto y funcionamiento en ONIA siguen `UNKNOWN`; aquí no se hizo dispatch ni se tocaron credenciales o sesiones.
