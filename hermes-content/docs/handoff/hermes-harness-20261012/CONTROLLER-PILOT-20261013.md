# Controlador local sintético — 13-oct-2026

**META:** ejecutar una meta pública de prueba de punta a punta sobre la cola SQLite existente. **PRUEBA:** `python -m unittest -v test_controller_pilot.py` y `python controller_pilot.py` desde este directorio. **PARADA:** sólo `FakeReadOnlyClient`, `FakeSessionFactory`, `account_scope=fixture-only`, objetivo `SYNTHETIC:` y presupuesto ficticio de una unidad; `SQLiteQueue.dispatch_external` sigue cerrado. No usar esta CLI con tareas, clientes, sesiones, cuentas, Telegram o proveedores reales.

El demo crea un SQLite temporal propio, encola una meta ONIA sintética, reclama owner, guarda checkpoint, rota a un **ID de sesión fake** por lectura de contexto sintética cercana al umbral, verifica fencing del owner anterior, ejecuta una vez el cliente fake de solo lectura, pasa QA determinista y espera una aprobación `fixture-sergio` ligada a cartera y hash del resultado antes de cerrar. Imprime sólo estado, etapas, número de llamadas fake, número de relevos y digest. No crea un chat Codex/Claude ni invoca modelo.

El núcleo reutilizado es `sqlite_pilot.py`: lease, fencing, checkpoint, handoff/ACK, resultado y `needs_reconcile`. Un error después de iniciar el cliente fake queda ambiguo y bloquea nuevos claims, sin reenvío automático. Una interrupción después de guardar el resultado en QA reanuda desde el checkpoint sin segunda llamada. Contexto ausente/viejo/incompleto detiene el paso. La lectura `U/W` del demo es **fixture**, no telemetría de un proveedor. La política local rota cuando `U + reserva >= min(500000, techo(0.70 × W))`; la reserva mínima de 16 unidades ficticias incluye el siguiente paso. La aprobación fake no autentica a Sergio ni representa consentimiento para efectos reales.

El puerto `ReadOnlyClient` hace explícito el contrato futuro, pero el controlador rechaza por tipo cualquier cliente distinto de `FakeReadOnlyClient`. Esto conserva el piloto ejecutable y cerrado. Para un modelo real aún faltan identidad, cuota y costo vigentes, control de herramientas/red y retries, recibos de modelo servido, política de datos y QA de efectos; el canario Codex VPS autorizado por separado no convierte este piloto en runtime operativo. La cola es de un solo host, sin scheduler, entrega, persistencia entre hosts ni continuidad PC apagada.
