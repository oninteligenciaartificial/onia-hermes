# Bolivian Electric Priority Proposal - Executive Team 2026

Estado: propuesta operativa para mandos/encargados
Fecha: 2026-06-23
Uso: presentar a gerencia operativa, marketing, ventas, administracion y areas
con autoridad de ejecucion. No incluye informacion confidencial de duenos.

## Resumen

La propuesta inicial no es reemplazar sistema actual ni empezar con un chatbot conectado a
WhatsApp. La mejor entrada es una fase corta para ordenar los puntos mas
urgentes:

1. seguimiento de cotizaciones y clientes;
2. mejora de web y experiencia de cotizacion;
3. base de conocimiento comercial;
4. capacitacion practica de IA para el equipo;
5. demo controlada de chatbot interno;
6. discovery de inventario con camara desde celulares.

El objetivo es mostrar resultados rapidos sin tocar datos sensibles ni frenar la
operacion diaria.

## Diagnostico visible

Fuentes publicas revisadas:

- `https://www.bolivianelectric.com.bo/`
- `https://www.sistema actualbolivia.com/`

Bolivian Electric ya tiene una base importante: catalogo, cotizacion online,
sucursales, lineas de producto, alquileres, manuales, workshops, redes y un ERP
externo. El problema probable no es falta de herramientas, sino falta de una
capa simple para que el equipo pueda:

- registrar y seguir cada consulta;
- responder mas rapido;
- convertir preguntas repetidas en contenido y respuestas;
- saber que cliente esta pendiente;
- saber que cotizacion necesita seguimiento;
- mejorar la experiencia despues de que el cliente pide cotizacion;
- usar IA de forma segura en tareas diarias.

## Que se recomienda empezar primero

### 1. CRM ligero de cotizaciones

Problema:

- las consultas pueden entrar por web, telefono, WhatsApp, redes, correo o
  sucursal;
- si no hay estado visible, se pierden seguimientos;
- cada area puede terminar usando su propio metodo.

Primera entrega:

- tablero simple: nuevo, contactado, cotizado, seguimiento, ganado, perdido;
- responsable por consulta;
- fecha de proxima accion;
- canal de entrada;
- sucursal/departamento;
- producto o linea consultada;
- reporte semanal.

Valor:

- menos cotizaciones olvidadas;
- mayor orden comercial;
- gerencia puede ver pendientes sin pedir planillas.

### 2. Web y experiencia de cotizacion

Problema:

- la web muestra productos y cotizacion, pero hay que validar si el cliente
  llega rapido al contacto correcto;
- un formulario incompleto puede generar mucho ida y vuelta;
- si no se registra el lead, no se mide conversion.

Primera entrega:

- auditoria de flujo web actual;
- propuesta de formulario de cotizacion mas claro;
- datos minimos por tipo de cliente;
- CTA por ciudad/sucursal o tipo de consulta;
- conexion del formulario al CRM ligero o tablero provisional.

Valor:

- mas claridad para el cliente;
- menos preguntas repetidas;
- mejor medicion de consultas reales.

### 3. Base de conocimiento comercial

Problema:

- mucho conocimiento tecnico vive en vendedores, manuales, catalogos, WhatsApp o
  experiencia de pocos;
- marketing puede necesitar informacion tecnica para publicar mejor;
- nuevos empleados tardan en aprender respuestas frecuentes.

Primera entrega:

- FAQ interna;
- plantillas de respuesta;
- guias por linea de producto;
- respuestas aprobadas para vendedores;
- insumos para contenido tecnico.

Valor:

- respuestas mas rapidas;
- capacitacion interna mas facil;
- menos dependencia de una sola persona.

### 4. Capacitacion IA para empleados

Problema:

- usar IA sin metodo puede generar datos falsos o exponer informacion interna;
- no todos saben convertir IA en ahorro de tiempo real.

Primera entrega:

- taller practico de 90 a 120 minutos;
- ejemplos de ventas, administracion, marketing y gerencia;
- reglas de seguridad: que se puede subir y que no;
- plantillas de prompts para trabajo diario.

Valor:

- el equipo aprende a redactar, resumir, ordenar y preparar respuestas sin
  reemplazar criterio humano.

### 5. Chatbot interno o demo controlada

Problema:

- conectar WhatsApp productivo antes de ordenar permisos Meta, numeros y
  respuestas aprobadas puede bloquear el proyecto;
- si hay varios numeros por departamento, primero hay que mapearlos.

Primera entrega:

- demo interna con preguntas frecuentes;
- rutas por sucursal/departamento;
- respuestas aprobadas;
- captura de datos minimos;
- derivacion humana.

Valor:

- valida el bot sin comprometer canales oficiales;
- prepara la futura conexion a WhatsApp cuando Meta y permisos esten listos.

### 6. Inventario con camara - discovery

Problema:

- antes de crear una app de inventario hay que saber si hay codigos, ubicacion,
  procesos de entrada/salida y diferencias con sistema.

Primera entrega:

- recorrido por almacen;
- mapa de codigos, etiquetas y ubicaciones;
- flujo de conteo desde celular;
- riesgos de sincronizar con sistema actual;
- alcance de MVP con camara.

Valor:

- define si conviene app PWA, QR/codigo de barras, fotos, exportacion o solo
  auditoria de conteo.

## Fase 1 recomendada

Nombre:

```text
Diagnostico operativo + capacitacion IA + piloto comercial inicial
```

Duracion:

```text
7 a 10 dias habiles
```

Inversion referencial:

```text
Bs. 1.900 a Bs. 2.900
```

Recomendacion comercial ONIA:

- usar Bs. 1.900 si se quiere abrir la oportunidad rapido y con alcance cerrado;
- usar Bs. 2.900 si incluye entrevistas con varias areas y documento ejecutivo
  mas completo.

Incluye:

1. reunion inicial con responsables;
2. entrevistas cortas con ventas, marketing, administracion y almacen;
3. revision de web, cotizacion y canales de contacto;
4. mapa de numeros/departamentos/sucursales;
5. capacitacion IA inicial;
6. seleccion de un mini piloto;
7. propuesta de Fase 2.

No incluye:

- conexion productiva de WhatsApp;
- integracion directa con sistema actual;
- automatizaciones con datos sensibles;
- cambios en servidores;
- migracion de datos;
- publicacion de contenido sin aprobacion;
- soporte permanente.

Rango referencial:

- reporte semanal de pendientes;
- capacitacion de equipo involucrado.

## Fase 3 propuesta

Nombre:

```text
Capa operativa ONIA sobre sistema actual y canales existentes
```

Alcance posible:

- dashboard de ventas/cotizaciones;
- inventario con camara MVP;
- tablero de importaciones;
- tablero de gastos y alertas;
- automatizaciones con aprobacion humana;
- WhatsApp oficial cuando Meta este listo;
- conector autorizado si hay reportes aprobados, API o permiso tecnico.

Esta fase se cotiza despues de la Fase 1 porque depende de datos reales,
permisos, procesos y riesgos tecnicos.

## Roles necesarios

De Bolivian Electric:

- sponsor interno con autoridad;
- responsable de ventas;
- responsable de marketing/canales;
- responsable de administracion o contabilidad;
- responsable de almacen;
- responsable tecnico de sistema actual o proveedor si se requiere integracion.

De ONIA:

```text
Responsable externo de IA, automatizacion y mejora operativa.
```

## Reglas de seguridad

- No pedir contrasenas al inicio.
- No tocar sistema actual sin aprobacion.
- No subir contratos, precios sensibles, costos, margenes o datos privados a IA
  externa.
- No publicar contenido sin aprobacion.
- No automatizar WhatsApp productivo hasta resolver Meta Business, numeros,
  permisos y responsables.
- Cada automatizacion debe tener responsable humano y forma de corregir errores.

## Resultado esperado en 30 dias

Al cerrar el primer piloto, Bolivian deberia tener:

- un mapa claro de problemas repetitivos;
- empleados capacitados en uso basico de IA;
- un tablero inicial de seguimiento;
- una base de conocimiento inicial;
- una demo de chatbot sin riesgo;
- una ruta clara para inventario, web, sistema actual y automatizaciones.
