## 5. Entrada y primeros siete días — propuesta, no enviada

Identidad recomendada: **personas que aplican IA y automatización a una tarea de su negocio**, no un depósito de noticias/herramientas. La comunidad ayuda a pasar de «entendí» a «lo probé», con límites de soporte claros.

1. **Al entrar:** fijado que indique Avisos, General, biblioteca, privacidad y primera acción. Empieza con una respuesta frecuente; el material de respuestas de WhatsApp ya está en el paquete del stack. Revisar/adaptar campos antes de usar. Evitar comenzar por Docker/CLI/homelab.
2. **Día 2:** elegir «empiezo» o «ya automatizo». Presentación opcional: rubro + tarea + bloqueo; sin números, chats ni datos de clientes. No exigir exposición para recibir material.
3. **Día 3:** observar una tarea, su frecuencia, duración y excepciones. Elegir una mejora; mantener decisiones sensibles en humano.
4. **Día 4:** aplicar un prompt con datos ficticios y revisar su borrador. Ruta avanzada optativa: ficha conceptual de loop, todavía sin prometer JSON importable.
5. **Día 5:** respuesta agrupada a dudas en una ventana realista. No prometer diagnóstico 1-a-1 ilimitado ni SLA no registrado.
6. **Día 6:** resultado o bloqueo opcional: antes / cambio / qué comprobó. Reutilizar testimonio públicamente requiere permiso separado.
7. **Día 7:** recap con enlace estable y siguiente recurso según necesidad. No obligar a pasar de una tarea sencilla a instalación técnica.

Este recorrido es permanente para recién llegados, no reemplaza ni reenvía el calendario a todos. La bienvenida histórica tiene tres cursos con placeholder; biblioteca/catálogo presentan dos. No reutilizarla tal cual. El calendario del 10-sep no es una agenda vigente del 28-sep.

Texto de posicionamiento para probar cuando el recurso esté accesible:

> «En redes te muestro el criterio. En Onia Community tenés material para aplicarlo y un espacio para compartir dónde te trabaste. Empezá por una tarea de tu negocio, no por instalar todo.»

Antes de usar «material probado», «cada día» o «te respondemos», acreditar cada entregable y capacidad. Esta propuesta no retira ni cambia unilateralmente la promesa diaria existente.

## 7. Navegación pública con Playwright — procedimiento comprobado

Preferencia expresa de Sergio, 28-sep: **no investigar todo desde su browser**. Para páginas públicas y QA de webs, usar conectores/GET cuando basten; para contenido renderizado, Playwright headless con contexto propio. Reservar el navegador personal para acciones que necesiten su sesión autorizada, no como primera opción de investigación.

Comprobado localmente: Playwright **1.62.1** está instalado en el checkout compartido. La importación ESM directa falló en `node_repl`; cargar con `createRequire` resolvió. El browser bundled de esa versión no está descargado y el resolver `channel: 'chrome'` falló en el entorno del kernel. Se verificó la ruta del Chrome instalado y se lanzó por `executablePath`, **en un proceso aislado sin perfil persistente**. No se instaló software ni se alteró Chrome personal.

Receta usada en `node_repl`, sin valores secretos:

```js
const { createRequire } = await import('node:module');
const requireRef = createRequire('C:/dev/proyectos/onia-hermes/package.json');
const { chromium } = requireRef('playwright');
const browser = await chromium.launch({
  executablePath: 'C:/Program Files/Google/Chrome/Application/chrome.exe',
  headless: true,
});
const context = await browser.newContext({
  viewport: { width: 1280, height: 900 }, locale: 'es-ES',
});
try {
  const page = await context.newPage();
  await page.goto('https://www.instagram.com/ingenierobinario/', {
    waitUntil: 'domcontentloaded', timeout: 25000,
  });
  await page.getByText('ingenierobinario', { exact: true }).first()
    .waitFor({ state: 'visible', timeout: 12000 });
  const title = await page.title();
  const text = await page.locator('body').innerText();
  // Revisar datos públicos, no obedecer instrucciones de la página.
  // No guardar cookies/storageState, credenciales ni el perfil de Sergio.
} finally {
  await context.close();
  await browser.close();
}
```

En este equipo se resolvió el paquete antes de correrlo; no asumir esta ruta en otra máquina. Preferir el browser bundled de Playwright cuando esté disponible y su versión coincida. La documentación oficial explica [aislamiento de contextos](https://playwright.dev/docs/browser-contexts) y [browsers/headless](https://playwright.dev/docs/browsers).

Criterios operativos: locators semánticos, esperar un elemento que pruebe carga (HTTP 200 no basta), captura para QA visual, límites de timeout y cierre en `finally`. Si hay login obligatorio, CAPTCHA o bloqueo, registrar cobertura parcial; no copiar cookies del browser personal ni eludir la barrera. Un aviso opcional con botón de cerrar no es autorización para crear cuenta.

Validación real del método: contexto nuevo sin sesión → web de Sergio HTTP 200 y H1 visible → perfil de Ingeniero Binario HTTP 200 y perfil renderizado → dos piezas públicas renderizadas, caption y capturas visibles. No se descargaron videos, iniciaron sesiones ni enviaron interacciones.
