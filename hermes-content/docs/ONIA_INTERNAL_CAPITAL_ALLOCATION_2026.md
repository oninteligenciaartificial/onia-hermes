## Home lab

El home lab sirve para reducir costos y acelerar pruebas, no para reemplazar
produccion critica.

Usos correctos:

- ambiente de desarrollo de Supabase/n8n/Open WebUI;
- almacenamiento local y backups de media/proyectos;
- pruebas de modelos locales para borradores, clasificacion, embeddings y RAG;
- procesamiento batch de assets internos;
- mirror de datos no sensibles para pruebas;
- laboratorio de ComfyUI/Wan si el hardware lo soporta.

Usos incorrectos:

- alojar servicios publicos de clientes desde internet de casa;
- guardar secretos sin cifrado;
- depender del home lab para cobros, demos o uptime comercial;
- exponer puertos sin VPN/tunel seguro;
- intentar reemplazar Higgsfield o cloud video antes de validar calidad/costo.

Reducir costos:

- usar modelos locales para borradores, resumen, clasificacion y research
  interno;
- usar almacenamiento local para material bruto en vez de subir todo a cloud;
- mantener staging local para no pagar otro VPS de pruebas;
- usar backups locales cifrados para no depender solo del servidor.

Inversion inicial recomendada:

- UPS/regulador para laptop/router/discos;
- SSD externo o disco de backup;
- RAM/SSD solo si el equipo actual lo soporta;
- Tailscale/Cloudflare Tunnel para acceso privado;
- no comprar servidor grande hasta medir uso real.

## Reglas de aprobacion de gasto

Sergio es el jefe y controlador de capital de ONIA.

Nadie puede aprobar con capital ONIA:

- compras de herramientas nuevas;
- pauta;
- equipo;
- inventario adicional;
- servicios externos;
- descuentos que bajen margen;
- promesas de entregas con costos ocultos.

Cada gasto debe tener:

1. centro: ONIA, Nuvia, ONIA Media, Home Lab, Cliente o Caja;
2. monto;
3. motivo;
4. retorno esperado;
5. responsable;
6. comprobante;
7. estado: solicitado, aprobado, comprado, usado, recuperado o perdido;
8. fecha de revision.
