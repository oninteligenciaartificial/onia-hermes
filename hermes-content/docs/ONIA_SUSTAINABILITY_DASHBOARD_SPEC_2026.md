# ONIA Sustainability Dashboard Spec 2026

Estado: interno Sergio/ONIA.
Fecha: 2026-06-21.
Uso: llevar estas reglas al dashboard / sistema operativo de ONIA.

## Veredicto

ONIA debe sobrevivir con matematica, no con intuicion.

Regla:

```text
El 40% Fondo ONIA sostiene la empresa. Nuvia y ONIA Media no pueden consumir
herramientas premium sin pagar su parte. Sergio gana mas cuando Sergio pone mas
capital, direccion, herramientas y riesgo.
```

## Cuanto debe vender ONIA para sostenerse con 40%

Gasto conservador mensual actual:

| Concepto | Monto |
|---|---:|
| Herramientas base registradas | Bs. 2.950,50 |
| Caja chica/logistica minima | Bs. 700,00 |
| Necesidad mensual conservadora | Bs. 3.650,50 |

Si el Fondo ONIA recibe 40% del ingreso neto operativo:

```text
Bs. 3.650,50 / 0,40 = Bs. 9.126,25
```

ONIA necesita aproximadamente Bs. 9.126 netos al mes para que el 40% cubra la
existencia mensual.

Meta semanal minima:

```text
Bs. 9.126 / 4 semanas = Bs. 2.282 por semana
```

Meta semanal sana:

```text
Bs. 2.500 a Bs. 3.000 cobrados por semana
```

## Ejemplos de ventas necesarias

Estos ejemplos asumen que el 40% se calcula sobre monto neto operativo. Si hay
costos externos, pauta, dominio, hosting, comisiones o herramientas de cliente,
se descuentan antes.

| Combinacion mensual | Venta neta | Fondo ONIA 40% | Resultado |
|---|---:|---:|---|
| 37 Auditorias Express de Bs. 250 | Bs. 9.250 | Bs. 3.700 | Cubre operacion, pero exige mucho volumen. |
| 7 Landings de Bs. 790 | Bs. 5.530 | Bs. 2.212 | No alcanza solo con landings. |
| 7 Web Profesionales de Bs. 1.500 | Bs. 10.500 | Bs. 4.200 | Cubre operacion y deja margen. |
| 4 Web Pro ONIA de Bs. 2.900 | Bs. 11.600 | Bs. 4.640 | Mejor equilibrio de volumen/margen. |
| 2 Implementaciones de Bs. 4.900 | Bs. 9.800 | Bs. 3.920 | Cubre operacion si el alcance esta cerrado. |
| 5 ONIA Motor Local Growth activos | Bs. 9.500 | Bs. 3.800 | Cubre operacion con recurrencia. |
| 1 Implementacion Bs. 4.900 + 1 Web Pro Bs. 2.900 + 1 n8n Bs. 790 + 2 Auditorias | Bs. 9.090 | Bs. 3.636 | Casi cubre; falta margen pequeno. |
| 1 Implementacion Bs. 6.500 + 1 Web Profesional + 2 Auditorias + 1 n8n | Bs. 9.290 | Bs. 3.716 | Cubre operacion. |

Lectura:

- ONIA no debe depender solo de auditorias.
- La mezcla sana es 1-2 tickets medianos + servicios pequenos.
- Webs, implementaciones y n8n cerrados son los que sostienen el 40%.
- ONIA Motor Local Growth debe ser el caballito recurrente: 5 clientes activos
  cubren la existencia conservadora.
- DentalGest/GestiOS ayudan mas por recurrencia, pero no deben comerse soporte
  no cobrado.

## Nuvia: Arthur Bs. 1.000 y Sergio Bs. 4.000

Si Arthur pone Bs. 1.000 y Sergio pone Bs. 4.000, el capital de lote queda:

| Persona | Capital | Participacion financiera |
|---|---:|---:|
| Sergio/ONIA | Bs. 4.000 | 80% |
| Arthur | Bs. 1.000 | 20% |
| Total lote/campana | Bs. 5.000 | 100% |

Regla:

```text
Arthur no va 50/50 si pone 20% del capital. Va 20% financiero, y puede ganar
variable adicional si trabaja y hay evidencia.
```

La variable operativa no es automatica. El dashboard debe obligar a elegir rol,
evidencia y aprobacion de Sergio antes de calcularla.

## Cierre Nuvia 80/20

Formula:

```text
Venta cobrada
- costo producto vendido
- empaque/bolsas/etiquetas
- transporte/envios
- comisiones/devoluciones
- Meta Ads
- Higgsfield/herramientas premium prorrateadas
= margen operativo

Margen operativo
- 20% Fondo ONIA
- 10% Reserva Nuvia
= utilidad distribuible
```

Luego:

1. Si Arthur no trabajo: utilidad distribuible se reparte 80% Sergio/ONIA y
   20% Arthur.
2. Si Arthur trabajo y hay evidencia: se puede pagar variable operativa segun
   escala, y el resto se reparte 80/20.
3. Si Arthur trabajo todo el cierre: su total puede acercarse a 30%-35%, pero
   no a 50% salvo que ponga 50% de producto, pauta y costos directos.

Escala operativa Arthur:

| Rol operativo | Variable |
|---|---:|
| Apoyo suelto, idea, grabacion simple o mensaje aislado | 0%-5% |
| Contenido aprobado sin responder leads | 5%-8% |
| Responde mensajes y registra leads | 8%-10% |
| Seguimiento completo y coordinacion | 10%-12% |
| Cierre real con evidencia | 12%-15% |
| Contenido + leads + seguimiento + cierre + entrega | 15%-20% |
| Excepcional aprobado antes, sin rescate Sergio | 20%-25% maximo |

Base:

```text
La variable se calcula sobre utilidad distribuible despues de Fondo ONIA y
Reserva Nuvia, no sobre ventas ni capital recuperado.
```

- si se reinvierte, el capital sigue registrado con la misma proporcion 80/20.

## Ejemplo Nuvia 80/20 con Arthur operando

Supongamos la misma utilidad distribuible: Bs. 1.820.

Arthur hizo seguimiento, respondio mensajes, cerro ventas y registro todo. Se
aprueba 12% variable operativa. Si tambien entrega, produce contenido y no
requiere rescate, podria subir a 15%-20%.

| Concepto | Monto |
|---|---:|
| Utilidad distribuible | Bs. 1.820 |
| Variable Arthur 12% | -Bs. 218,40 |
| Base restante para capital | Bs. 1.601,60 |
| Sergio/ONIA 80% | Bs. 1.281,28 |
| Arthur capital 20% | Bs. 320,32 |
| Arthur total | Bs. 538,72 |

Lectura:

- Sergio sigue ganando mas porque puso 80% del capital y asume ONIA.
- Arthur gana mejor si trabaja, pero no cobra como 50/50 financiero.
- ONIA ya recibio Fondo ONIA y Nuvia ya recibio reserva antes del reparto.

El dashboard debe mostrar advertencia si Arthur total supera:

| Capital Arthur | Techo total Arthur |
|---|---:|
| 0% | 20% ordinario; 25% excepcional aprobado antes |
| 1%-24% | 35% total |
| 25%-49% | 45% total |
| 50% de producto, pauta y costos directos | 50% total |

## Regla de Higgsfield para Nuvia

Nuvia no puede usar Higgsfield como si fuera gratis.

Higgsfield es gasto critico de ONIA. Si Nuvia lo consume sin control, puede
dejar a ONIA sin capacidad para clientes, demos y ventas.

Regla:

```text
Toda generacion premium de Higgsfield debe tener campana, objetivo, responsable,
aprobacion de Sergio y costo prorrateado a Nuvia si se usa para vender Nuvia.
```

Distribucion inicial recomendada del uso premium:

| Centro | Limite mensual sugerido |
|---|---:|
| ONIA clientes/demos comerciales | 60% |
| Nuvia | 20% |
| ONIA Media / canales | 10% |
| Investigacion/R&D | 10% |

Reglas:

- Nuvia no puede pasar de 20% sin aprobacion de Sergio.
- Si Nuvia supera su limite, el exceso se registra como costo directo de Nuvia.
- Si una pieza de Nuvia no se publica o no entra a una campana, queda marcada
  como perdida creativa y cuenta contra el limite.
- Arthur no puede pedir generaciones premium sin brief aprobado.
- Primero se prueba con guion, celular, foto real, edicion simple o self-hosted.
- Higgsfield se usa para finales premium, no para probar ideas sin filtro.

Campos para dashboard `premium_tool_usage`:

| Campo | Tipo |
|---|---|
| fecha | date |
| herramienta | Higgsfield / ElevenLabs / OpenAI / otra |
| centro | ONIA / Nuvia / ONIA Media / Cliente |
| campana_lote | texto |
| responsable | Sergio / Arthur / otro |
| aprobado_por | Sergio |
| objetivo | texto |
| costo_estimado_bs | numero |
| output_url | url/texto |
| estado | borrador / usado / publicado / rechazado / perdido |
| ingreso_asociado_bs | numero |
| decision | cobrar a centro / asumir ONIA / descartar |

## Self-hosted para ahorrar

No todo debe ir a herramientas pagadas. La regla es usar cloud premium solo para
lo que genera valor final.

### Ahorro inmediato

| Necesidad | Self-hosted / local | Que ahorra | Limite |
|---|---|---|---|
| Chat interno, prompts, SOPs | Open WebUI + modelos locales/API | Reduce uso disperso de chats pagos y centraliza prompts. | No reemplaza modelos premium para trabajo critico. |
| Control de costos LLM | LiteLLM | Permite presupuestos por equipo/centro y llaves separadas. | Requiere configuracion y disciplina. |
| Automatizaciones | n8n self-hosted | Evita pagar Zapier/Make por flujos propios. | Hay que controlar ejecuciones, logs y errores. |
| Datos/CRM | Supabase privado | Base unica para ONIA Center, Nuvia, leads y cierres. | RLS, backups y server-side obligatorio. |
| PDFs | Stirling PDF | Evita herramientas sueltas para contratos/reportes. | Debe estar protegido. |
| Busqueda/research | SearXNG / Crawl4AI privado | Reduce investigacion manual y scraping desordenado. | No usar para abuso ni datos sensibles sin permiso. |
| Video borrador | ComfyUI + Wan local/worker | Permite probar ideas antes de gastar Higgsfield. | Hardware actual puede limitar calidad/velocidad. |
| Storage bruto | Home lab / discos locales | Reduce nube para material pesado. | Backups cifrados y no exponer a internet. |

### Arquitectura recomendada para ahorro

```text
Idea / prompt / guion
  -> Open WebUI / modelos locales / Codex
  -> prueba visual con celular, edicion simple o ComfyUI/Wan si aplica
  -> solo los mejores conceptos pasan a Higgsfield
  -> resultado final se registra en ONIA Center
  -> si pertenece a Nuvia, se prorratea como costo Nuvia
```

### Reglas para no gastar tokens premium

1. Ningun prompt va directo a Higgsfield sin brief.
2. Cada idea debe tener objetivo comercial: venta, demo, cliente, producto o
   contenido de autoridad.
3. Maximo 1 ronda premium por pieza Nuvia sin aprobacion extra.
4. Si Arthur pide cambios, debe decir exactamente que problema corrige.
5. Si una pieza no se usa, se marca como perdida y cuenta contra Nuvia.
6. Si una pieza genera ventas, se asocia ingreso y se calcula ROI.
7. Si Nuvia quiere mas uso premium, debe salir de margen Nuvia o ser aprobado
   como inversion Sergio/ONIA.

## Modulos que debe tener el dashboard

### 1. Break-even ONIA

Objetivo: saber si el 40% cubre la empresa.

Campos:

- gasto mensual base;
- caja chica mensual;
- necesidad mensual;
- porcentaje Fondo ONIA;
- venta neta requerida;
- venta neta acumulada mes;
- falta para cubrir mes;
- semanas restantes;
- semaforo: rojo/amarillo/verde.

Formula:

```text
venta_requerida = necesidad_mensual / porcentaje_fondo_onia
fondo_actual = venta_neta_mes * porcentaje_fondo_onia
faltante_fondo = necesidad_mensual - fondo_actual
```

### 2. Simulador de servicios

Objetivo: saber cuantas ventas hacen falta.

Debe permitir combinar:

- auditorias;
- diagnosticos;
- landings;
- webs;
- Web Pro;
- n8n;
- implementaciones;
- SaaS mensual;
- ONIA Media Studio.

Salida:

- venta total;
- Fondo ONIA 40%;
- comisiones;
- utilidad Sergio estimada;
- riesgo de entrega;
- horas estimadas.

### 3. Capital Nuvia

- pieza sin campana;

- gasto premium sin ingreso asociado despues de 7 dias.

Campos:

- costo cloud evitado estimado;
- tiempo ahorrado;
- costo de operar;
- ahorro neto;
- riesgo tecnico;
- responsable.

### 7. Retiro Sergio / dueno

Objetivo: permitir que Sergio gane sin matar ONIA.

Campos:

- utilidad neta del mes;
- caja operativa disponible;
- meses de runway;
- capital Sergio pendiente de recuperar;
- retiro recomendado;
- retiro aprobado;
- motivo;
- semaforo.

Regla:

```text
Rojo: no retiro fijo.
Amarillo: 10%-20% utilidad neta.
Verde: 20%-30% utilidad neta.
Fuerte: hasta 40% si hay 3 meses de reserva.
```

## Decisiones para llevar al dashboard

1. El dashboard debe mostrar primero supervivencia ONIA, no ventas brutas.
2. Cada servicio debe mostrar cuanto aporta al 40%.
3. Nuvia debe cerrar por lote y campana, no por sensacion.
4. Arthur debe verse como capitalista proporcional cuando pone dinero, y como
   variable operativo cuando trabaja.
5. Higgsfield debe tener limite por centro y aprobacion Sergio.
6. Self-hosted debe medirse por ahorro real, no por instalar herramientas.
7. Sergio debe tener modulo de retiro/dueno con semaforo.
