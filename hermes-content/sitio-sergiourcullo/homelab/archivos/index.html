Los archivos del homelab

La guía pública explica qué hacer. Acá está hecho: tres archivos que copiás, pegás y corren. Cubren lo que más tiempo cuesta la primera vez y lo que casi nadie hace hasta que es tarde.

Leelos antes de correrlos

Los tres tocan tu máquina de verdad. Están comentados línea por línea justamente para que sepas qué hace cada una — no pegues nada que no entiendas, ni de acá ni de ningún lado.

Este link no está enlazado desde ninguna página. Es de la comunidad — si lo reenviás, dejás de tener algo que los demás no tienen.

1 · Primer arranque del servidor

primer-arranque.sh

Todo lo que hay que hacer después de instalar Ubuntu y antes de instalar nada más. Es el paso 2 de la guía, con las cuatro cosas que se olvidan siempre: la zona horaria, que Docker arranque solo, el firewall y los parches de seguridad automáticos.

#!/bin/bash
# Correlo UNA vez, recién instalado Ubuntu:  bash primer-arranque.sh
set -e

# 1. Zona horaria. Si no, el servidor trabaja en horario de Londres
#    y TODAS tus automatizaciones salen corridas cuatro horas.
sudo timedatectl set-timezone America/La_Paz

# 2. Actualizar todo lo que ya está instalado
sudo apt update && sudo apt upgrade -y

# 3. Docker, con el instalador oficial de get.docker.com
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh
sudo usermod -aG docker $USER
sudo systemctl enable docker   # arranca solo cuando vuelve la luz

# 4. Firewall: sólo SSH desde tu red local. Nada abierto a internet.
#    ⚠️ Cambiá 192.168.0.0/24 por el rango de TU casa si es distinto.
sudo ufw allow from 192.168.0.0/24 to any port 22
sudo ufw --force enable

# 5. Parches de seguridad solos, sin que tengas que acordarte
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

echo "Listo. Cerrá sesión y volvé a entrar para que Docker ande sin sudo."
ip a | grep "inet " | grep -v 127.0.0.1   # anotá esta IP
La línea del firewall es la que hay que mirar dos veces. Si el rango de tu casa no es 192.168.0.x, cambiala antes de correr el script — si no, te quedás afuera de tu propio servidor y hay que ir con monitor y teclado. El comando de la última línea te dice cuál es tu rango.

2 · Respaldo automático

respaldo.sh

Lo que casi nadie hace hasta el día que el disco no arranca. Copia todos los volúmenes de Docker —o sea, los datos de todo lo que tengas corriendo— a otro disco, y borra los respaldos de más de un mes para no llenarlo.

#!/bin/bash
# Respaldo de los volúmenes de Docker.
# ⚠️ DESTINO tiene que ser OTRO disco. Respaldar al mismo disco no
#    sirve de nada: si muere, se lleva el respaldo también.
set -e
DESTINO="/mnt/respaldo"
FECHA=$(date +%Y-%m-%d)

mkdir -p "$DESTINO/$FECHA"

# Un .tar.gz por volumen
for VOL in $(docker volume ls -q); do
  echo "respaldando $VOL"
  docker run --rm \
    -v "$VOL":/origen:ro \
    -v "$DESTINO/$FECHA":/destino \
    alpine tar czf "/destino/$VOL.tar.gz" -C /origen .
done

# Borra lo de más de 30 días
find "$DESTINO" -maxdepth 1 -type d -mtime +30 -exec rm -rf {} \;

echo "Listo: $DESTINO/$FECHA"
du -sh "$DESTINO/$FECHA"

Para que corra solo todas las noches a las 3:

crontab -e
# y pegá esta línea al final:
0 3 * * * /bin/bash /home/TU-USUARIO/respaldo.sh >> /var/log/respaldo.log 2>&1
Un respaldo que nunca probaste no es un respaldo. Una vez al mes, agarrá un .tar.gz y descomprimilo en una carpeta cualquiera para confirmar que adentro está lo que tiene que estar. Toma dos minutos y es la diferencia entre tener copia y creer que tenés copia.

3 · La lista de la BIOS

checklist-bios.txt

No es un script: son las cuatro opciones que hay que cambiar en la BIOS para que la máquina se comporte como servidor y no como computadora de escritorio. Se entra apretando Supr o F2 apenas prende.

[ ] Restore on AC Power Loss  ->  Power On
    La más importante. Sin esto, vuelve la luz y la máquina
    se queda apagada esperando que alguien apriete el botón.

[ ] Wake on LAN               ->  Enabled
    Te deja prenderla desde el celular sin ir hasta donde está.

[ ] Halt on errors            ->  No errors
    Si no, un teclado desconectado la deja trabada en el
    arranque. Y el servidor no va a tener teclado.

[ ] Boot order                ->  el disco primero
    Con el pendrive de instalación olvidado adentro, arranca
    del pendrive y creés que se rompió todo.
La segunda y la tercera parecen menores y son las que te hacen bajar al sótano. Un servidor de verdad tiene que poder arrancar solo, sin monitor, sin teclado y sin nadie mirando.
