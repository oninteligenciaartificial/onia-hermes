Bóveda · arquitectura · nuevo

Automatización, agente o loop.

No son sinónimos. La pregunta no es “¿puedo poner IA?”; es qué forma tiene el trabajo y cómo sé que terminó bien.

Qué no hace

Un agente no vuelve inteligente un proceso mal definido. Puede interpretar lenguaje, pero no debería inventar precios, aprobar pagos ni decidir excepciones comerciales. La parte crítica sigue teniendo una regla y una persona responsable.

02

Cuándo un agente sí ayuda

Cuando alguien normalmente tiene que leer e interpretar

Un mensaje como “necesito una página urgente para mi restaurante” no entra en un `IF` simple. Un agente puede devolver una salida estructurada:

{
  "categoria": "web",
  "urgencia": "alta",
  "requiere_humano": true
}

El paso siguiente no lo decide el modelo: un `IF` revisa `requiere_humano`. Si es verdadero, `Telegram / Send Message` avisa a una persona. Si es falso, el workflow puede registrar la consulta o mandar la siguiente pregunta. El agente interpreta; el workflow controla la ruta.

03

Qué es un loop útil

Revisar hasta que un estado cambie, con límite y salida

Schedule Trigger  inicia cada 10 minutos
  ↓
HTTP Request  consulta el estado de un pago
  ↓
IF  status = paid
  ├─ true  → registrar y avisar
  └─ false → Wait 10 minutos → volver a consultar

Un loop sin tope puede gastar API, duplicar avisos o seguir para siempre. Definí una salida: por ejemplo, máximo seis intentos; si no cambia el estado, `Telegram` escala a una persona. Esperar también es lógica, no una pausa decorativa.
