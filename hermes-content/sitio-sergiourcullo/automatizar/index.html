Bóveda · n8n · nuevo

Elegí qué automatizar primero.

No empieces por n8n, Zapier o Make. Empezá por una tarea que se repite, tarda y cuesta cuando sale mal. Esta es la regla que uso antes de abrir un workflow.

Qué no hace

Esta matriz no te dice que automatices todo. Si la tarea necesita criterio comercial, una excepción frecuente o una conversación delicada, primero ordenala de forma manual. Automatizar confusión sólo hace que el error vaya más rápido.

01

La matriz de prioridad

Puntuá cada proceso antes de elegir una herramienta

PreguntaSi la respuesta es sí
¿Pasa varias veces por semana?Suma repetición
¿Alguien copia, busca o responde lo mismo?Suma tiempo
¿Un olvido pierde un lead, una venta o una cita?Suma costo de error
¿La regla se puede escribir en una frase?Es candidata a automatizar

Empezá por la tarea con más “sí”. Un ejemplo bueno: cada formulario de una web entra al correo, alguien lo copia a una planilla y después avisa por WhatsApp. Hay repetición, tiempo perdido, posibilidad de olvido y una regla clara.

02

Dibujá el proceso en cinco casillas

Si no podés explicarlo así, todavía no abras n8n

  1. Entrada: qué evento real lo inicia. Ejemplo: llega un POST /demo-lead desde tu formulario.
  2. Dato mínimo: qué tiene que venir. Ejemplo: name, phone, service, source.
  3. Regla: qué se considera válido. Ejemplo: teléfono y servicio no vacíos.
  4. Salida: dónde queda la evidencia. Ejemplo: una fila en Google Sheets o en tu CRM.
  5. Excepción: qué pasa si falta algo. Ejemplo: no se registra como lead completo y se pide el dato faltante.
La salida no es “que llegue un mensaje”. Tiene que quedar un registro que otra persona pueda revisar después. Si no, el proceso sigue dependiendo de la memoria de alguien.
03

El workflow mínimo en n8n

Funciona sin IA porque las reglas ya son fijas

# lead de formulario
Webhook  POST /demo-lead
  ↓
IF  phone is not empty AND service is not empty
  ├─ true  → Google Sheets / Append Row
  │           ↓
  │         Telegram / Send Message al responsable
  └─ false → responder: “falta teléfono o servicio”

Probá las dos ramas. Mandá un lead completo y uno sin teléfono. Si la rama falsa sigue registrando el lead como completo, tu automatización está mintiendo. Si la rama verdadera no deja una fila y un aviso, no tenés evidencia de que funcionó.

Recién cuando este flujo funcione de punta a punta evaluá IA: por ejemplo, para leer un mensaje libre y clasificarlo antes del IF con Basic LLM Chain + Structured Output Parser (cómo). No uses un modelo para comprobar si un campo está vacío.
