01

Claude y Claude Code no son lo mismo

Entender · 7 minutos · al terminar sabés cuál de los dos necesitás

En una línea: Claude te dice cómo hacerlo; Claude Code lo hace, en tu computadora, tocando tus archivos. Uno es un consejero, el otro es un empleado.

¿Cuál necesitás vos? Si lo que querés es preguntar, redactar y pensar decisiones, con el chat te alcanza y no gastes más. Claude Code se justifica cuando hay trabajo que hacer sobre archivos reales: armar una página, ordenar datos, escribir y ejecutar automatizaciones. En el video te muestro los dos lado a lado haciendo la misma tarea, para que la diferencia se vea en vez de creerme.

Y una cosa que confunde a todos: se paga una sola suscripción para ambos. No son dos productos que comprás — son dos formas de usar lo mismo, y la mayoría paga creyendo que contrató al empleado cuando sólo está usando al consejero.

02

Instalarlo, y tu primera skill

Usarlo · 10 minutos · al terminar lo tenés andando

requiere plan pago necesita Node.js macOS · Windows · Linux

Los tres pasos del video

  1. Bajá Node.js de nodejs.org (botón verde, versión LTS, siguiente-siguiente). Es lo que le da a tu terminal el comando npm — sin esto, el paso 2 no existe.
  2. Abrí la terminal e instalá Claude Code con el comando de abajo. En Windows, la terminal es PowerShell; en Mac, la app Terminal.
  3. Entrá y comprobá. Escribís claude, iniciás sesión con tu cuenta paga, y listo.
# 2 · instalar (después de Node.js)
npm install -g @anthropic-ai/claude-code

# 3 · comprobar que quedó bien
claude --version   # imprime el número de versión
claude doctor      # revisa la instalación entera

# abrí la terminal EN LA CARPETA de tu proyecto y:
claude

¿Y dónde lo instalo? ¿En qué computadora?

En la tuya de todos los días — la que usás para trabajar. Claude Code trabaja donde estás vos, sobre tus carpetas y tus archivos. No hace falta ninguna máquina especial.

El servidor (esa PC vieja que capaz me viste mostrar — el homelab) es otra cosa: ahí corre lo que Claude Code te ayuda a construir, las automatizaciones que quedan trabajando solas día y noche. Primero instalás Claude Code en tu compu; el servidor viene después, cuando ya tengas algo que dejar corriendo.

Tu primera skill — qué es eso

Una skill es una carpeta con un archivo de texto donde le escribís a Claude Code cómo hacés VOS una tarea: tu formato de cotización, tu forma de responder, tus reglas. Se la escribís una vez y la usa siempre — es la diferencia entre repetirle las instrucciones cada día y tener un empleado que ya conoce la casa. En el video escribimos la primera, juntos, en unos minutos.

En Windows instalá también Git for Windows. Sin eso varias cosas se comportan distinto. Y si la terminal te da miedo, existe la app de escritorio: hace lo mismo con ventanas.
03

Que trabaje sin vos

Soltarlo · 10 minutos · al terminar sabés qué dejarle corriendo solo

hooks · subagentes · conectores · horarios con la parte que sale mal

En una línea: primero le enseñás, después lo soltás. Claude Code tiene cuatro funciones para trabajar sin que estés en la habitación — pero con reglas tuyas, no con fe.

Los cuatro escalones

  1. Hooks — «cada vez que pase esto, hacé aquello». No lo decide Claude: lo ejecuta tu computadora, siempre. Los míos: antes de escribir un archivo, revisar que no rompa la configuración; después de escribir, anotar qué tocó; al terminar, formatear, revisar tipos, y commitear a GitHub.
  2. Subagentes — le delega a otro. Le das UNA tarea y la reparte: uno revisa la seguridad, otro corre las pruebas, otro relee lo que hicieron los demás. Trabajan en paralelo y cada uno abre limpio — el que revisa tu código no es el que lo escribió, y por eso ve lo que el otro no vio. Se describen en texto: un archivo por agente, qué hace y cuándo llamarlo.
  3. Conectores — manos fuera de tu computadora. Conexiones que salen hacia otras aplicaciones. Los míos: n8n (donde viven mis automatizaciones), Cloudflare (mis dominios y proyectos, gratis y con planes desde $5), y Meta (anuncios, mensajería, Instagram, WhatsApp). Le preguntás por tu negocio y va a mirar de verdad.
  4. Horarios — el único que no te necesita. Cada hora revisa la cola de tareas; cada dos, la web de venta; cada tres entra como cliente y avisa si algo se rompió. Corre en tu compu prendida o en un servidor, sin vos.

Mi caso, con números

4 hooks que se disparan solos · 3 subagentes con su tarea · 6 conectores hacia afuera · 4 trabajos por horario. Todo eso vive en una PC de escritorio prendida. Nada más.

La parte honesta — lo que corre solo, falla solo

Publicó algo a medias: mi hook de cierre subió 200 líneas antes de que existiera lo que usaba. Un servicio corrió tres semanas sin publicar nada — nadie se enteró porque no fallaba, simplemente no hacía nada. Y hoy, cuatro de mis seis conectores no andaban: dos caídos, dos sin permiso, y no avisó ninguno. Cuando se caen, nadie te avisa: entrás, revisás y los volvés a conectar.

Las tres reglas antes de automatizar algo

  1. Que avise cuando falla, no cuando funciona. Un aviso que llega siempre se vuelve invisible en una semana.
  2. Que mida el resultado. Terminar sin error no prueba que hizo algo: contá lo que salió, no lo que corrió. Yo tenía automatizaciones «todo verde» que no corrían nada.
  3. Ponele techo al gasto. Cuando el mío se disparó 74%, era UN trabajo mal configurado. Se baja el consumo — no se sube el tope.
