2. Qué ocurre dentro de un turno de Hermes

1 · Preparar

Arma el prompt con el pedido, contexto del proyecto, memoria y herramientas habilitadas.

2 · Consultar

Envía al modelo elegido por el proveedor. El LLM responde texto o solicita herramientas.

3 · Controlar

El runtime valida argumentos, permisos, backend y ejecución. Un prompt no sustituye una barrera real.

4 · Observar

El resultado de la herramienta vuelve al contexto. No reemplazarlo con una salida inventada.

5 · Continuar o cerrar

El LLM vuelve a decidir. Cierra con evidencia o con un bloqueo concreto; no por una promesa.

La documentación oficial describe este ciclo. La configuración local y la sesión concreta determinan modelo, herramientas, límites y entorno. Ver la investigación adjunta para fuentes y diferencias entre versión instalada y documentación actual.

Modelo ≠ agente ≠ worktree

Sol/Luna son modelos. Hermes/Codex/Claude son programas de agente. Orca organiza sesiones. Un worktree separa cambios Git, no es un contenedor de seguridad ni sincroniza la conversación.

Memoria ≠ entrenamiento

Historial, memoria persistente y skills son mecanismos diferentes. Guardar una lección permite reutilizarla; no actualiza los pesos del LLM ni prueba que la siguiente ejecución vaya a cumplirla.

Capacidad ≠ activación

Hermes ofrece cron, perfiles, bots y kanban. Esta investigación no los activa. Tenerlos disponibles no justifica otra cola ni una segunda coordinación general.
