- Credenciales: hay prácticas de manejo de secretos y ejemplos `sk-*`; no autorizan acceso. No se usó credencial ni se inspeccionó configuración.
- Pruebas: common impone 80%+ y unit/integración/E2E de forma general; no equivalen a validar el contrato. Code review, desarrollo y Git repiten agentes/TDD/commit. No hallé regla de trato: siguen usted para clientes, vos para marca y permisos/gasto/MFA reservados.

5. Priorizar pruebas de contrato; aplicar umbral 80% solo si el proyecto/CI lo requiere. No borrar reglas de lenguajes por falta de uso actual.
